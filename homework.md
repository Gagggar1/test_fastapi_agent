# Домашнее задание: Интеграция AI-агента через FastAPI

## 1. Структура POST-запроса и JSON-ответа (Базовая версия)

### Структура POST-запроса к FastAPI-сервису
Для отправки данных агенту клиент выполняет HTTP POST запрос (например, на эндпоинт `/chat`). Тело запроса в формате JSON имеет следующую структуру (описанную Pydantic-моделью):

```json
{
  "text": "Привет! Сколько будет 2 умножить на 15?",
  "session_id": "session-12345"
}
```
**Описание полей:**
* `text` (строка, обязательно) — текст запроса от пользователя, который будет передан агенту в Langflow.
* `session_id` (строка, опционально) — уникальный идентификатор сессии пользователя для сохранения контекста диалога.

### Структура JSON-ответа от FastAPI
После обработки запроса в Langflow, наш FastAPI-сервис возвращает клиенту следующий JSON:

```json
{
  "input": "Привет! Сколько будет 2 умножить на 15?",
  "auth_used": "bearer",
  "result_text": "2 умножить на 15 будет 30.",
  "raw": { ... }
}
```
**Описание полей:**
* `input` — исходный запрос пользователя (эхо).
* `auth_used` — метод авторизации, который успешно сработал при обращении к Langflow.
* `result_text` — извлеченный текстовый ответ от LLM-агента.
* `raw` — полный JSON-ответ от сервера Langflow (полезно для отладки).

## 2. Улучшение API (Добавление `user_id` и `processing_time_ms`)

В качестве улучшения добавим передачу `user_id` для аналитики и персонализации, а также логирование времени обработки запроса `processing_time_ms`.

### Обновленная структура POST-запроса:
```json
{
  "text": "Привет! Сколько будет 2 умножить на 15?",
  "session_id": "session-12345",
  "user_id": "tg_user_987654321",
  "mode": "short"
}
```
*Добавились:*
* `user_id` (строка, обязательно) — идентификатор пользователя из внешней системы.
* `mode` (строка, опционально) — режим работы (например, "короткий" или "развернутый" ответ).

### Обновленная структура JSON-ответа:
```json
{
  "input": "Привет! Сколько будет 2 умножить на 15?",
  "result_text": "30",
  "user_id": "tg_user_987654321",
  "processing_time_ms": 1245
}
```
*Изменения:*
* Добавлено `processing_time_ms` (целое число) — время в миллисекундах, затраченное на ожидание ответа от Langflow.
* Убрано поле `raw`, так как в рабочей версии (продакшен) клиенту не нужно видеть внутреннюю структуру Langflow.

## 3. Использование API в разных интерфейсах

Наш FastAPI-сервис выступает универсальной точкой входа (Proxy), но клиенты (Telegram-бот и Веб-форма) будут формировать запросы по-разному.

### Интерфейс 1: Telegram-бот
**Как используется:** Бот (например, написанный на aiogram) принимает сообщение от пользователя Telegram и перенаправляет его в наш FastAPI.
**Формат запроса (особенности):**
* `user_id` берется напрямую из объекта `message.from_user.id` (ID пользователя в Telegram).
* `session_id` можно сделать равным `message.chat.id`, чтобы бот помнил контекст в рамках конкретного чата.
* **Пример формирования:**
  ```json
  {
    "text": "Расскажи шутку",
    "session_id": "chat_11223344",
    "user_id": "tg_11223344",
    "mode": "detailed"
  }
  ```

### Интерфейс 2: Веб-форма (Lovable / React)
**Как используется:** Пользователь заходит на сайт, вводит текст в поле и нажимает кнопку "Отправить".
**Формат запроса (особенности):**
* `user_id` берется из системы авторизации сайта (если пользователь залогинен) или генерируется как временный `fingerprint` (например, `guest_abc123`).
* `session_id` генерируется на фронтенде (случайный UUID) при загрузке страницы и сохраняется в `localStorage` браузера.
* **CORS:** При отправке запроса браузер обязательно отправит `OPTIONS` запрос (pre-flight). FastAPI должен ответить правильными CORS-заголовками (`Access-Control-Allow-Origin`), иначе браузер заблокирует запрос.
* **Пример формирования:**
  ```json
  {
    "text": "Расскажи шутку",
    "session_id": "8f3a9b2c-1234-5678",
    "user_id": "guest_abc123",
    "mode": "short"
  }
  ```

**Главное отличие:** В Telegram идентификаторы (`user_id`, `session_id`) даны самой платформой и неизменны, а в браузере (веб-форме) фронтенд должен сам их генерировать, сохранять и управлять ими, а также заботиться о CORS-политиках браузера.

## 4. Подготовка к Production: Что нужно добавить в сервис?

Чтобы безопасно использовать этот FastAPI-сервис в продакшене, необходимо внедрить следующие механизмы:

1. **Авторизация клиентов (API Keys для эндпоинтов):** Сейчас FastAPI скрывает ключ от Langflow, но сам он открыт всем. Нужно добавить проверку `X-API-Key` или `Authorization: Bearer` в самом FastAPI, чтобы только наши доверенные клиенты (наш TG-бот или наш фронтенд) могли слать запросы.
2. **Rate Limiting (Ограничение запросов):** Запросы к LLM стоят денег. Нужно добавить лимиты (например, с помощью библиотеки `slowapi`), чтобы один `user_id` или IP-адрес не мог отправить больше 10 запросов в минуту. Это защитит от DDoS-атак и спама.
3. **Строгая валидация входящих данных:** Ограничить длину поля `text` в Pydantic-модели (например, добавить `Field(max_length=1000)`), чтобы пользователи не отправляли слишком длинные тексты и не тратили все токены разом.
4. **Изоляция и скрытие ошибок:** Полностью убрать поле `raw` из ответа. Если Langflow падает или не отвечает, клиенту нужно возвращать красивое сообщение (например, "Сервис временно недоступен"), а не сырой трейсбек с ошибкой таймаута (Security by Obscurity).
5. **Асинхронное логирование:** Записывать каждый запрос (с `user_id`, `processing_time_ms` и статусом) в базу данных или систему логирования (ELK, Datadog) для мониторинга затрат и аналитики поведения пользователей.
